# 개선 후보

0.4.2 기준으로 정리한 다음 작업 후보와 근거. 숫자는 Galaxy S23 Ultra 실측.

## 지금 상태

- **추적**: 등반 영상 30개 점검(TrackAudit + `prototype/tools/audit_tracks.py`)에서 엉뚱한 대상을 따라가거나(MISMATCH·SMALL) 멈춘(FROZEN) 구간이 실제로는 남아 있지 않다. 남은 표시는 오탐 1개(20260927_122338~2 7.5–9.0s, 뒤쪽 사람 박스가 연달아 잡힘).
- **분석 속도**: 영상 길이의 약 1.0~1.1배. 40초 영상(20261011_105654) 단계별 시간(`OnDeviceBenchmark.benchmarkAnalysisBreakdown`):

  | 단계 | 시간 | 비고 |
  |---|---|---|
  | 사람 검출기(efficientdet_lite2, GPU) | 15.8s | 1회 약 90ms, 0.4.2에서 호출 170 → 125 |
  | 포즈 추정(GPU) | 11.2s | 1회 약 28ms |
  | 디코딩 등 | 7~9s | 하드웨어 디코더 처리량이 대부분(640px 출력) |
  | 흐름용 회색조 · 색 특징 · 잘라서 포즈 | 약 4s | |

  측정마다 폰 상태(발열 등)로 ±20% 흔들린다 — 비교는 같은 실행 안에서 하거나 호출 수처럼 결정적인 값으로.

## 알려진 문제

- **사람으로 잡힌 큰 홀드에서 시작(20260914_160135, 0.4.4)**: 등반자가 처음 큰 볼륨 앞에 서 있던 영상에서, 검출기가 그 볼륨을 사람으로 잡고 포즈 모델이 그 위에 가짜 포즈(몸 168px)를 내 첫 포즈가 된다. 이후 '등반자 크기' 기준이 그 가짜 포즈라 진짜 등반자 박스(580px)는 너무 크다고 빠지고, 0.4.4는 처음 12초를 홀드에 머문다(0.4.3은 7.5초). 해결 방향: 움직이지 않는 '등반자'를 잡고 있는데 다른 곳에서 사람이 움직이면 그쪽으로 바로잡기, 첫 포즈 확인에 움직임 조건 추가.

## 검토했지만 하지 않기로 한 것

- **가벼운 검출 모델(efficientdet_lite0)**: 1회 62ms(lite2 대비 1.5배 빠름)지만 lite2가 찾는 등반자 크기(높이 0.15 이상) 박스의 74%만 찾는다.
- **검출기 입력을 미리 줄이기(640px)**: 줄이는 비용 때문에 오히려 느려짐(94 → 101ms).
- **보정 검출 간격 넓히기(0.5s → 1.5s)**: 검출기 호출의 37%지만, 움직이지 않는 박스(홀드를 사람으로 잡은 박스) 판별이 최근 검출 기록에 기대고 있어 위험.
- ~~**화면 전체에서 찾은 포즈도 색 확인 필수로**: 색 확인 없이 받은 경우가 7,667번 중 53번(0.7%)뿐이고 점검에서 문제가 된 적 없음.~~ → 0.4.4에서 적용(20260525_093059에서 그 0.7%가 30초 놓침의 시작이었다).

## 작업 방법 메모

- 추적을 바꾸면: 핵심 단위 테스트(`android/core`) → 실기기 TrackAudit(`-e audit sample -e out audit_vN`) → `audit_tracks.py compare` → 문제 영상은 `sheets/` 그림으로 직접 확인.
- 실기기 테스트는 `adb shell am instrument -w com.zzick.debug.test/androidx.test.runner.AndroidJUnitRunner`(connectedAndroidTest는 테스트 영상을 지운다). 화면이 잠기면 UI 테스트가 "No compose hierarchies"로 실패.
- 분석 결과가 달라지는 변경이면 `AnalysisCodec.VERSION`을 올려 예전 저장본을 버리게 한다.
